# Architecture notes

## Routing

- Audio sessions on all active render endpoints are enumerated
  (`IAudioSessionManager2`); new sessions and device changes are signalled via
  `IAudioSessionNotification` / `IMMNotificationClient`.
- Each session's process is mapped to its top-level window. Audio helper
  processes without windows (Chrome/Edge audio service, Firefox content
  processes, ...) are resolved via the parent process chain; UWP apps via their
  `ApplicationFrameWindow`. The foreground window wins if a process has several.
- `MonitorFromWindow` gives the display. Displays are identified by their
  monitor device path, so assignments survive reboots and port renumbering.
- Window moves are tracked with `SetWinEventHook` (foreground, move/size end,
  location change, restore), throttled to 80 ms, plus a 2 s safety poll.
- Routing uses `IAudioPolicyConfigFactory::SetPersistedDefaultAudioEndpoint`
  (undocumented, Windows 10 1803+ / Windows 11, both known interface IIDs are
  tried).

## Settings UI: loaded only while it is open

The settings UI lives in `MonitoneSettings.dll`. `Monitone.exe` loads it with
`LoadLibrary` when the window opens and unloads it with `FreeLibrary` when it
closes; idle Monitone carries no UI code, no WebView2 and no browser process.

- The DLL runs its window on its own STA thread (a WebView2 requirement), so
  the UI can never stall routing. Calls back into the application are
  marshalled to the main thread with `SendMessage`.
- Exe and DLL talk through a small versioned C interface
  (`src/SettingsApi.h`). Both link the C runtime statically and have separate
  heaps, so no C++ object or heap allocation crosses the boundary.
  Configuration changes go through the INI file.
- On close the DLL destroys its windows, unregisters its classes, releases
  WebView2 and waits until WebView2 has released every callback object; only
  then may it be unloaded. If that does not happen within 5 seconds it pins
  itself rather than risk WebView2 calling into freed code.
- The WebView2 browser processes exit when the WebView is released.
- `SettingsModule` (exe side) checks after `FreeLibrary` that the module is
  really gone and logs via `OutputDebugString` otherwise.

## Configuration file

The settings window writes
`%APPDATA%\Monitone\Monitone.ini`:

```ini
[General]
Balance=off            ; off | monitor | window
RestoreOnExit=1
PollMs=2000            ; safety poll interval, 250..60000
Paused=0

[Monitors]
Count=2
[Monitor0]
Key=\\?\DISPLAY#DEL41B8#...      ; monitor device path
Gdi=\\.\DISPLAY1
Name=DELL U2720Q
Device={0.0.0.00000000}.{...}   ; render endpoint id

[Apps]
Count=2
[App0]
Exe=discord.exe
Action=pin             ; pin | exclude
Device={0.0.0.00000000}.{...}
[App1]
Exe=teams.exe
Action=exclude
```

## Source layout

| File | Purpose |
| --- | --- |
| `src/main.cpp` | Entry point, single instance, COM apartment |
| `src/TrayApp.*` | Tray icon, menu, WinEvent hooks, message loop |
| `src/Engine.*` | Per-tick evaluation: session -> window -> display -> rule |
| `src/AudioRouter.*` | Endpoints, sessions, change notifications |
| `src/PolicyConfig.*` | Per-application output device (undocumented API) |
| `src/WindowMap.*` | Process -> representative window, parent chain |
| `src/SettingsModule.*` | Loads, drives and unloads the settings DLL |
| `src/SettingsApi.h` | C interface between `Monitone.exe` and `MonitoneSettings.dll` |
| `src/Config.*`, `src/Monitors.*`, `src/Balance.*`, `src/Autostart.*`, `src/Shell.*` | `monitone_core`, shared by exe and DLL |
| `src/settings/` | `MonitoneSettings.dll`: UI thread, WebView2 window, bridge to the web UI |
| `src/IdentifyOverlay.*`, `src/TestTone.*` | "Identify displays" overlay, WASAPI test tone (DLL) |
| `ui/` | Settings UI (HTML, CSS, JavaScript), embedded into the DLL |
| `tools/ui-preview/` | Renders the UI in Chromium with a mock bridge, no Windows needed |
| `res/Monitone*.ico`, `res/*.svg` | App and tray icons, generated by `tools/icon/make_icon.py` |
| `res/*.rc`, `res/Monitone.manifest` | Icons, version resources, embedded UI files, manifest |
| `src/Win32.h` | RAII wrappers for handles, COM, registry, menus, icons |
